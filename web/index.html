3 · Settings

How much conversation the model can remember. Longer uses more memory.
How the context (KV cache) is stored. Smaller leaves room for a longer context, or for more of the model in VRAM: watch the purple part of the bars. 8-bit and 4-bit use flash attention.
Faster replies with the same answers: the model's small built-in draft layer guesses the next few words, and the model checks them all in one pass. Helps most when the model doesn't fit in VRAM.
Used for any work that runs on the CPU. On laptops, fewer threads is often faster.
Advanced
Faster attention that reads the context once. Turn off only to compare or troubleshoot.
Tokens read at once when processing a prompt. Bigger is faster for long prompts but needs more memory.
How many experts each layer uses per token. Fewer is faster but lower quality.
Only consider the k most likely next words. 0 = no limit.
Only consider the most likely words that add up to this share of the probability.
Drop words less than this fraction as likely as the top choice. Cuts nonsense at higher temperatures.
-1 is random. Any other number makes replies repeatable at the same settings.
Automatic uses experts in RAM for mixture-of-experts models and whole layers for the rest. Experts in RAM: the GPU does all the attention and the CPU only the few experts each word picks, much faster for MoE models (Qwen3.6-35B-A3B on an RTX 3070 laptop: 33 against 13 tok/s). Whole layers: the GPU and CPU hand over once per word; best for dense models.
With several cards of the same kind, tierlm fills the best one, then the next, then RAM. Off: only the best card (and RAM). A much slower second card can cost more than its memory brings, and keeping the busiest experts in VRAM works with one card for now; Find the fastest settings measures both ways and keeps the faster.
Mixture-of-experts models split with experts in RAM: tierlm learns which experts this model uses most as you chat, and the next time it loads, puts those in VRAM instead of whole expert layers. Off by default: whether it beats the plain split depends on the PC. Find the fastest settings learns the experts straight away, measures both and turns this on only if it wins.
Goes with the setting above: while you chat, experts the conversation keeps using move into VRAM in place of ones it stopped using (a few per word, copied from RAM). Helps when a chat is about something different from what the model learned, such as code after a lot of plain text. Uses more RAM: the experts in VRAM are kept in RAM as well. Works even before tierlm has learned anything about the model.
0 uses all free VRAM. A lower number keeps VRAM free for other apps, or lets you see how the model would run on a smaller GPU.
Ignore the GPU and run everything on the CPU. Useful for troubleshooting.
Finding the fastest settings

    Connect other apps

    OpenAI-compatible API
    Apps that work with OpenAI (Open WebUI, Continue, LibreChat, scripts using the OpenAI library) can use tierlm instead: give them the address below as the base URL. They use the model loaded here, or load another one by name (the names are listed at /v1/models).
    Let other computers, phones, or Open WebUI running in Docker reach tierlm over your network. Off: only this computer can. Anyone on your network can use your GPU while this is on, so set an API key too. Windows may ask whether to allow tierlm through the firewall: choose Private networks.
    API key
    When set, apps must send it as their API key, and the tierlm page asks for it on other devices. Needed if you open tierlm to the internet through a tunnel (Cursor works that way).

    Set up an app

    Ready-made settings for the loaded model: its name, context length, tool calling and this address.
